# USB setup transaction, offline pass 4

This new native module prepares a descriptor-derived setup plan and models ownership, initialization and rollback. It has **not opened a Virus** and is not yet the complete device owner. Unknown or vendor-specific audio layouts are refused; live descriptors are needed to determine whether the user's Virus fits the supported path.

## Implemented

`make_plan` requires explicit capture/playback interface numbers, alternate settings and endpoint addresses. It accepts only USB2 full/high speed, UAC1 AudioStreaming Type-I PCM with exactly 16 bits in two bytes or 24 bits in three bytes, 44.1/48 kHz advertised by a valid format descriptor, and supported isochronous data endpoint capacities/intervals. It rejects conflicting alternates, unavailable rates, pitch/lock-delay/padding requirements and unknown synchronization endpoint references. Channels and packing come from descriptors; no VID/PID-to-model mapping or endpoint guessing occurs. A multi-rate endpoint without sampling-frequency control is refused. An immutable Plan supplies the existing audio engine's Config.

`Session` checks the active configuration instead of changing it, opens selected interfaces, reads every original alternate before mutation, selects alternates, reads every controllable endpoint's existing rate, and then sets the requested rate. Capturing all rates before writes prevents losing a shared-clock baseline through sequential read/write. Backend start receives the validated audio config and an explicit future service ordinal. Zero and misaligned high-speed ordinals are refused; no arbitrary frame lead is supplied.

On failed setup, failed start or normal stop, rates and alternate settings are restored in reverse order before interfaces close. Failed mutations are conservatively included in rollback because failure alone does not prove that the device remained unchanged. A failed start can leave accepted transfers; owners remain alive in `draining` until the backend reports terminal completion of all I/O. There is no timeout-based fabricated drain. Rollback failure is reported as `uncertain`, which cannot be retried on the same session. Destruction with pending I/O terminates to prevent freeing live request storage.

`iousbhost_controls.mm` contains actual compiled IOUSBHost synchronous request helpers for GET_CONFIGURATION, GET_INTERFACE and UAC1 endpoint GET_CUR/SET_CUR sample-frequency controls. They use one-second control timeouts, exact transfer counts, little-endian three-byte sample rates and unchanged output on read failure. The write helper can restore any observed nonzero 24-bit baseline rate; new stream plans remain limited to 44.1/48 kHz. Helpers require already-owned objects and must run on a control executor, never the DAW audio callback. They do not open, reset, capture, select a configuration or issue firmware commands.

## Evidence and limits

Saved kernel `PGDevice::startStreaming` at 0x113b0 (`ev_c9a1b1b944c7dd0b5f0f1292d4bf994689b7f69edd6a79b71e9b2c5197c8299f`) invokes sample-frequency setup before `resumeStreaming`. `PGKernelDeviceVirus::setFrequency` at 0x1ed52 (`ev_93c97d7fc814a2344ebae8a1de3e8e999588a8969ad0284f9d290a868f4acad6`) constructs a three-byte class endpoint SET_CUR request. Broad multi-vendor configuration/reset paths are deliberately not reconstructed as an automatic initialization recipe. Source binary SHA-256: `7308f591d634625acfaa0019f218af99e04cf936b4dfe18227a0bbf28a67e539`.

Descriptor layouts and controls follow the [USB-IF Audio 1.0 specification](https://www.usb.org/sites/default/files/audio10.pdf) and [Audio Data Formats 1.0](https://www.usb.org/sites/default/files/frmts10.pdf). The installed macOS SDK's IOUSBHostObject/Interface headers define request, selection and ownership APIs. The state machine is a new host-side design, not recovered vendor source.

No concrete Backend currently opens interfaces, constructs pipes or connects this Session to the audio Engine; this boundary remains explicit. A future owner must verify exact registry identity, use one serial queue for interfaces/engine/callbacks, bind correct pipes after selecting alternates, retain owners through real callback drain, and invalidate/recreate pipes when alternate settings change. A static plan does not establish device readiness or audio clock lock. Baseline rates are sampled after selecting the streaming alternate, so rollback restores that observed rate and the original alternate; it cannot promise that selecting an alternate had no other device-wide clock effects. Device-specific startup commands, MIDI-interface ownership, feedback topology, configuration changes and reconnect are not implemented.

## Verification

Run `sh native/usb-session/build_and_test.sh`. On this arm64 host, native and ASan/UBSan tests passed: strict descriptor selection and malformed format rejection, every structural truncation of the synthetic descriptor fixture, setup failure at all eleven backend operations, mutation-before-failure rollback, reverse restoration, no teardown before callback drain, partial-start failure, restart, rollback uncertainty and high-speed frame alignment. Sanitized Objective-C test doubles verified actual request bytes, exact-length rejection, bounded timeout and read-output preservation. No USB device/interface object was constructed, and no USB I/O occurred.
